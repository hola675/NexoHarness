# Source of Truth

NexoHarness has one canonical source. Harness-specific output is generated by adapters and is never maintained as a second manual implementation.

## Directory ownership

| Directory | Ownership | Classification |
|---|---|---|
| `core/` | Foundational principles, schemas, contracts, directives and policies | CANONICAL |
| `core/contracts/` | Canonical Contract definitions | CANONICAL |
| `agents/` | Canonical agent behavior | CANONICAL |
| `skills/` | Reusable procedures | CANONICAL |
| `rules/` | Behavioral invariants | CANONICAL |
| `workflows/` | Coordination and state transitions | CANONICAL |
| `capabilities/` | Abstract tool requirements | CANONICAL |
| `profiles/` | Capability bundles | CANONICAL |
| `enforcement/` | Runtime and structural protections | CANONICAL |
| `evals/` | Behavioral expectations and evaluation definitions | CANONICAL |
| `observer/` | Runtime evidence and observation outputs | RUNTIME |
| Shared runtime state (conceptual; no directory reserved) | Scoped operational evidence and learned recommendations | RUNTIME |
| `adapters/` | Harness translation logic | CANONICAL implementation boundary |
| `research/` | External investigation and comparison | RESEARCH |
| `third-party/` | Provenance and license metadata | RESEARCH |
| `dist/` | Generated harness-native output | GENERATED |
| `installer/` | Future installation and verification tooling | RUNTIME / GENERATED boundary |
| `tests/` | Structural, integration and regression checks | VALIDATION |

Phase 0.0 through 0.2 create the directory shape and canonical definitions and validation foundation only. Empty canonical directories do not imply production behavior exists. The root `AGENTS.md` is repository development guidance; `core/directives/core-directive.md` is the product's canonical runtime directive. `observer/` is runtime evidence storage and is never a canonical authoring root.

## Definitions

- **CANONICAL** — authored source that defines intended behavior or its assurance requirements. It must remain harness-neutral where the architecture requires it.
- **GENERATED** — derived output produced by an adapter or build step. It must not be used as authoring input or edited manually.
- **RUNTIME** — evidence, execution or installation material used while the system operates. Runtime data cannot silently redefine canonical behavior.
- **RESEARCH** — external material used to inform design. Research is not a runtime dependency and requires provenance review before adaptation.

## Ownership rules

1. Canonical behavior is authored once.
2. Adapters may translate canonical definitions but may not redefine them.
3. Generated output may be deleted and regenerated from canonical inputs.
4. Observer evidence may produce proposals, never automatic promotion.
5. External sources remain research until license, provenance and evaluation requirements are satisfied.

## Learned runtime boundary

Canonical source describes intended behavior. Learned runtime state describes observed operational evidence and is not canonical. It may inform selection among already-authorized choices, but it cannot alter authority, weaken policy or become canonical authoring input by itself. Any canonical improvement must pass the proposal, evaluation, regression comparison, independent review, explicit approval and promotion lifecycle in `core/policies/self-improvement.md`.
